# Poe Effort & Points Monitor

面向 macOS Safari + Userscripts、Chrome + Tampermonkey 的 Poe 用户脚本。脚本固定聊天阅读位置、保护 Effort 选择，并显示 Poe 原生剩余积分百分比。

## 安装

### Safari + Userscripts

1. 从 Mac App Store 安装 Userscripts，在 Safari“设置 > 扩展”中启用。
2. 将网站访问范围限制为 `poe.com`，并把 [Poe_Effort_Points.user.js](./Poe_Effort_Points.user.js) 放入 Userscripts 的脚本目录。
3. 替换已有脚本后，在 Safari 的 Userscripts 扩展弹窗中点击 `Refresh view`，再重新载入 Poe 页面；如需授权页面访问，只允许 `poe.com`。
4. 展开页面右上角面板，确认有“固定阅读位置（阻止自动跳动）”开关且已开启，“阅读位置”显示“已固定，可手动滚动”。仅核对磁盘文件不能证明当前页面已加载新版；若没有这个开关，打开 Userscripts 应用确认 `Save Location`，再重新扫描和加载页面。

### Chrome + Tampermonkey

1. 从 [Tampermonkey 官方网站](https://www.tampermonkey.net/)安装扩展。
2. 在 Tampermonkey 新建脚本，把 `.user.js` 全文粘贴并保存。
3. 确认脚本只匹配 `poe.com`，然后刷新页面。

脚本没有自动更新地址。安装新版本时，需要手动替换用户脚本内容或文件。

## 页面状态与设置

页面角落的简洁状态栏显示：

`本次用量：220 积分　剩余：6%　Effort：Low`

“本次用量”现在指**当前聊天最近一轮回复的实际费用**。旧聊天中接着提问、连续发送、新建聊天均按一轮一轮显示，新一轮费用会替换上一轮；不累计整段聊天。打开或刷新有回复的聊天时，会自动补读最近一轮。

展开状态栏可看到积分重置时间和五个开关：自动 Low、发送保护、严格保护、固定阅读位置和调试日志。绝对剩余积分不会显示。颜色跟随系统深浅主题，状态栏固定在页面顶部右侧。

### 固定阅读位置

默认开启“固定阅读位置（阻止自动跳动）”。不论回复正在生成还是已经结束，停在哪段文字就保持在哪里，Poe 自动向上或向下滚动时会恢复阅读位置。在底部阅读时也不会自动跟随新输出。

- 滚轮、触控板、触屏垂直滑动、滚动条、方向键、PageUp / PageDown、空格及 Home / End 可以主动移动阅读位置。每次手动移动后立即固定在新位置，不会短暂放行 Poe 的自动跳动。
- 右上角状态栏下方提供常驻的“回到底部”按钮，无需展开设置。能按文字或无障碍标签识别的 Poe 原生“回到底部”按钮也可继续使用。点击只跳到当时的底部；之后继续生成时，再次保持阅读位置。
- 到过底部后再向上转动滚轮，立即按这次操作固定新位置。鼠标仍停在原生或脚本的“回到底部”按钮上时，也能直接用滚轮向上读。
- 加载上方历史消息、图片改变尺寸、文字换行时，优先保持正在阅读的文字在屏幕中的位置，而不是死守同一个滚动数值。仅在内存中保留页面节点与位置，不复制或保存聊天正文。
- 初次载入或切换聊天时，先允许 Poe 恢复该聊天的初始位置，再启用固定；这段等待不会在每次手动滚动后重复。同一聊天重新创建滚动容器时继承原阅读位置，不重新放行底部跟随。立即手动滚动也会立即启用固定。
- 不接管侧栏、输入框、菜单和代码块自身的滚动，也不接管横向滚动或缩放。关闭该开关后移除本功能添加的滚动样式和事件处理，恢复 Poe 原有行为。

展开面板的“阅读位置”一行显示是否已固定。未发现聊天消息或滚动区域时显示“等待聊天”，不会去锁住其他页面区域。本功能不增加扩展权限，也不修改 Poe 页面运行的 JavaScript 方法。

### Effort

- 页面打开、模型或聊天变化时检测 Effort；同一 URL 内的模型控件变化也会触发重新检测。
- 控件尚未加载时会有限重试。持续的消息文本变化不会不断推迟扫描。
- 只在找到与 Effort 明确关联且包含 Low 的控件时操作；切换后重新读取页面状态验证。无 Low 选项或无法确认控件时不猜测。
- 当前手动选择较高档会保留到切换聊天或模型；操作 Effort 菜单时会暂停自动切换。
- 界面将未知、不支持和 Effort 的真实 `None` 档都简写为 `None`；展开后的状态说明保留内部判断。

发送保护可在点击、Enter 或表单提交前核对状态。若必须先自动切到 Low，会在页面确认前拦住原发送；期间聊天、模型、输入或 Effort 选择发生变化时，会取消本次恢复并提示重新检查。Enter 的保护不会代替用户再次按键。Safari 或 Poe 若不允许取消事件，保护不能保证绝对拦截。

脚本在 Poe 页面 DOM 就绪后读取持久化设置，再启用自动操作。调试日志只记录状态和耗时，不记录聊天正文。

## 积分数据的准确性

- 剩余百分比优先采用 Poe 页面原生显示；例如页面显示 14%，脚本显示 14%。余额与额度周期无法明确对应时不自行计算。
- 设置页的绝对积分数只在内部用于解析和重置信息，不展示，也不会用余额差值当成单条费用。
- 已在真实 Poe 页面确认只读路径：`/chat/<chatCode>` 的内嵌数据提供回复的 `messageId`、`messageCode` 和 `responsibleJob.jobId`；`/message/<messageCode>` 的内嵌数据提供 `responsibleJob.totalCostPoints` 和结算状态。脚本通过后台 GET 读取这两个官方页面，不切走当前聊天、不展开消息菜单、不修改输入，不调用未验证的接口。
- 只有聊天、回复、计费任务均对应且任务已完成时，才显示官方总费用。该数字已包含输入、输出及折扣；不再将这些条目相加，也不将用户消息重复计费。相同回复与任务的重复观察不会重复读取详情；重试生成的新任务分别核对。
- 不同聊天及标签页分别核对当前回复，聊天同名不影响归属；不使用全账户余额差值来分摊单轮费用。内存缓存最多保留 100 条已结算记录，刷新后重读，不保存聊天正文。
- 本次用量是事后账单统计，不是发送前费用预测。多标签页可能让余额变化无法归属于单条消息。

| 场景 | 本次用量显示 |
| --- | --- |
| 新聊天尚无回复 | `待发送` |
| 正在补读已有回复 | `读取中` |
| 已发送、正在回复或官方尚未结算 | `待结算` |
| 官方明确结算为 0 | `0 积分` |
| 官方完成结算 | 该轮实际积分数 |
| 读取失败、资料缺失或归属不匹配 | `未知` |

回复完成后立即读取；需要等待结算时，按第 2、5、10、20 秒有限重查，整个读取周期不超过 30 秒。超时后保留待结算或未知，展开说明可见重试已停止；返回标签页时重新核对。切换聊天会取消旧请求，旧结果不能更新新聊天。一次新发送等待期间不会拿上一轮费用来冒充当前费用。只读最近一轮，因此无需加载完整历史。

## 隐私与来源

积分读取使用原脚本的 Poe 设置页 GET，加上已实测的当前聊天页与当前回复消息资料页 GET。优先使用浏览器同源请求，自动沿用 Poe 页面现有登录会话；只有没有原生请求能力时才使用 GM API。Safari 的扩展请求曾返回不匹配的资料，同源请求已在真实 Safari 页面成功读取费用。脚本不读取或上传 Cookie、Token、API Key，不访问非 Poe 站点，不修改 Poe 后端接口或计费流程。

积分显示逻辑保留并注明原作者 xiadengma 与来源：[原文](https://blog.xiadengma.com/posts/poe%E6%98%BE%E7%A4%BA%E6%B6%88%E8%80%97%E7%A7%AF%E5%88%86%E8%84%9A%E6%9C%AC/) · [原始 v1.4 源码](https://gist.githubusercontent.com/XIADENGMA/62e1239fdbd9c9b7ca0da285c2756fd1/raw/Poe_show_points_usage.user.js)。本脚本没有沿用原脚本的自动更新地址。

## 测试与实测范围

运行本地自动测试：

```sh
node --test test/Poe_Effort_Points.test.cjs
node --check Poe_Effort_Points.user.js
```

滚动功能需要浏览器的真实排版与滚动事件。运行本机验证页：

```sh
node test/serve-scroll-lock.cjs
```

打开终端给出的本机地址（默认 `http://127.0.0.1:8769/`），点击“运行浏览器检查”。端口占用时可通过 `POE_SCROLL_TEST_PORT` 指定另一个端口。按 Ctrl+C 停止服务。验证页直接加载同一份用户脚本，使用模拟消息检查连续生成与跳动、连续手动滚动、历史加载、上方内容尺寸变化、键盘、触屏、滚动条、代码块与输入框隔离、正向及反向列表、整页滚动、聊天和容器切换、开关保存及页面缓存恢复。验证不会访问 Poe 或发送问题。

自动测试覆盖 Effort 文本识别、原生剩余百分比解析、官方费用解析、单轮替换与重复观察、真正零费用、结算延迟、聊天隔离、请求取消和旧结果丢弃。还通过模拟浏览器原生请求及 GM 的回调、Promise API，执行实际 `PointsService` 的完整读取流程。测试样例仅保留脱敏后的消息、聊天和计费结构，不包含聊天内容；这些模拟测试不能替代真实 Safari/Poe 事件验证。

本次原有自动测试 29/29 通过，后台浏览器的本机验证页 28/28 场景通过；另用真实滚轮输入核对持续输出、底部自动跟随和向上离开底部。验证页的“体验底部自动跟随场景”可同时模拟新回复的横向裁剪外框、窗口层滚轮接管、滚动回调拉到底部及持续输出；停止体验会移除这些模拟行为。

1.2.0 在用户 Safari 实测中仍出现“到过底部后向上滚动又被拉回”的问题。1.2.1 修复了可能误认新回复外框的问题，在窗口层接收滚轮和滚动事件，并避免脚本自己的位置纠正再次触发页面跟随。新增场景已在本机复现旧版失败并验证修复。

2026-10-31 实际检查发现：虽然磁盘安装文件已经是 1.2.1，Safari 原页面仍显示没有阅读保护开关的旧版面板。让扩展重新扫描、重新载入页面后，真实页面才出现并开启阅读保护。在独立的 Poe / GPT-4o-mini 聊天中，已验证生成期间到底部再上滚、生成结束后的保持和继续上滚；重新加载页面后又重复三次生成中的到底部再上滚。每次对照截图的指定已完成文字区域像素完全一致。过程及原图见 [Safari 真实验收记录](./test/safari-acceptance-20261031.md)。本轮未修改滚动代码，修正的是扩展及页面实际加载状态和安装验收流程。Poe 改变消息标识或滚动区域结构时，需要在真实页面重新核对。

此前积分功能的实测记录（不包含本次滚动功能）：2026-10-30 已在真实 Poe 页面核对 GPT-4o 一轮官方费用为 220 积分，确认聊天与消息资料页均在服务器返回的数据中提供所需字段。Safari Userscripts 已安装当时的修复版，实测能显示该轮 220 积分；切换另一历史聊天后，显示该聊天最近一轮 661 积分，也与其官方消息资料一致；新建空聊天显示“待发送”。当时自动测试 29/29 通过。真实发送、取消/重试、慢加载及点击/Enter 保护，仍应在用户正常使用中核对，本次不发送专用测试消息。
